# Комплексный технический аудит проекта DiaNight

**Дата проведения:** 11 октября 2026 г.  
**Проект:** DiaNight (com.diaclock.nightstand)  
**Платформа:** Android (Java 8, Gradle 8.7, AGP 8.4.0)  
**Целевые SDK:** `minSdk 19` (Android 4.4 KitKat), `targetSdk 33`, `compileSdk 33`

---

## 1. Резюме и назначение проекта
**DiaNight** — специализированное медицинское приложение-ночник (DiaClock / Nightstand) для непрерывного прикроватного мониторинга уровня глюкозы крови, отображения текущего времени, статуса активного инсулина (IoB), уровня заряда батареи и оповещения о критических состояниях (гипогликемия / гипергликемия).

Данные поступают по локальной сети из **xDrip+ Web Service** (порт 17580), удаленного **Nightscout** или через локальные широковещательные интенты `com.eveningoutpost.dexdrip.BgEstimate`.

## 2. Архитектура и структура кода

### 🔴 Проблемы:
1. **Монолитные Activity (God-Objects):**
   - `MainActivity.java` (~1800 строк) и `SettingsActivity.java` (~1460 строк) содержат в себе абсолютно всё: работу с сетью, парсинг JSON, синтез PCM звука, аппаратное управление камерой/вспышкой, управление радиомодулем Wi-Fi, сканирование локальной сети, сохранение настроек и рендеринг UI.
   - Полное отсутствие разделения на слои (Data / Domain / Presentation) или архитектурных паттернов (MVVM / MVI).
2. **Дублирование кода между Activity:**
   - Алгоритмы сканирования подсети (порты, потоки) частично продублированы в `MainActivity` и `SettingsActivity`.
   - Проверка и парсинг версий релизов GitHub для автообновления дублируются.
3. **Управление фоновыми потоками:**
   - В коде используются конструкции вида `new Thread(...)` без использования единого `ExecutorService` с привязкой к жизненному циклу Activity (например, при тихом поиске мастера в сети, перезапуске Wi-Fi).

### 🟢 Сильные стороны:
- Отсутствие тяжелых сторонних фреймворков и библиотек, быстрая компиляция и низкий оверхед по памяти.
- Плавный UI, минимальное время старта на слабых старых устройствах.

## 3. Медицинская безопасность и надёжность мониторинга (Диабет)

### 🔴 Критические риски:
1. **Отсутствие Foreground Service (Фоновой службы мониторинга):**
   - Мониторинг сахара и тревоги работают **только пока `MainActivity` находится на переднем плане**.
   - Если Android закроет приложение при нехватке оперативной памяти (Low Memory Killer) или если пользователь случайно свернет приложение: **ТРЕВОГИ ПРЕКРАТЯТ ЗВУЧАТЬ**.
   - Для приложения ночника критически важен `Foreground Service` с постоянным уведомлением и приоритетом `START_STICKY`, чтобы система не выгружала его ночью.
2. **Тихий поиск подсети блокируется без API Secret:**
   - В `triggerSilentSubnetAutoDiscovery()`:
     ```java
     final String secret = cachedSecretHash;
     if (secret == null || secret.isEmpty()) return;
     ```
     Если у пользователя локальный xDrip+ настроен без пароля (API Secret не заполнен), автоматический поиск сервера при смене IP-адреса **полностью отключается**.
3. **Спящий режим и питание:**
   - В `AndroidManifest.xml` запрошен `WAKE_LOCK`, но `PowerManager.WakeLock` в коде нигде не создается и не удерживается. Удержание экрана реализовано только через `android:keepScreenOn="true"` в XML разметке. Если экран погаснет по тайм-ауту системы, CPU устройства заснет, сетевые опросы прекратятся.

## 4. Аппаратное взаимодействие и системная совместимость

### 🟡 Средние риски и замечания:
1. **Управление вспышкой (Camera Flash Alarm):**
   - В `setHardwareTorchMode()` для `CameraManager` берется первый попавшийся ID: `ids[0]`. На современных устройствах (Pixel, Samsung, Xiaomi) с несколькими камерами `ids[0]` нередко является фронтальной камерой без LED-вспышки, из-за чего вспышка не сработает. Необходимо проверять `CameraCharacteristics.FLASH_INFO_AVAILABLE`.
2. **Wi-Fi Watchdog на Android 10+:**
   - Метод `wm.setWifiEnabled(false)` / `true` является `deprecated` с Android 10 (API 29) и заблокирован Google для сторонних приложений. На современных смартфонах сторожевой таймер перезапуска Wi-Fi не сможет перезагрузить адаптер.
3. **Регистрация BatteryReceiver на API 34+:**
   - `registerReceiver(batteryReceiver, filter, Context.RECEIVER_NOT_EXPORTED)` для системного липкого интента `ACTION_BATTERY_CHANGED` выбросит исключение `SecurityException` при повышении `targetSdk` до 34+.

### 🟢 Сильные стороны:
- **Защита OLED от выгорания:** `pixelShiftRunnable` со случайным смещением каждые 2 минуты защищает экран при длительной непрерывной работе ночью.
- **Диммирование яркости:** Корректное масштабирование цвета через HSV Value (V-компоненту), позволяющее плавно приглушать текст без искажения цветовых оттенков.
- **Встроенный синтезатор `SoundGenerator`:** Прямая генерация PCM-звуков через `AudioTrack (MODE_STATIC)` на потоке `STREAM_ALARM`. Звуки гарантированно проигрываются независимо от наличия файлов на диске и системных мелодий.

## 5. Безопасность и Сеть

1. **Permissive SSL / Ослабленная проверка сертификатов:**
   - В `HttpClientProvider` для Android 4.4–5.0 (API 19–21) включен `X509TrustManager`, принимающий любые сертификаты, и `hostnameVerifier` возвращающий `true`. Это было вынужденным решением для обхода устаревших корневых сертификатов на KitKat (для GitHub API и локальных HTTPS), но делает устройство уязвимым к MITM при подключении к недоверенным сетям Wi-Fi.
2. **Хранение секретов:**
   - API Secret и IP-адреса сохраняются в стандартном открытом `SharedPreferences` (`DiaClockPrefs.xml`).
3. **Разрешение Cleartext HTTP:**
   - В манифесте включен `android:usesCleartextTraffic="true"`, что необходимо для локального порта `17580` xDrip+, но требует осторожности.

## 6. Качество кода и тестирование

1. **Покрытие тестами:**
   - Unit-тесты отсутствуют (0%). Папка `app/src/test` пуста.
   - Нет тестов на критические вычисления: конвертацию мг/дл в ммоль/л, логику попадания в диапазоны гипо/гипер, проверку ночных/дневных порогов.
2. **Сборка и зависимости:**
   - Используется `OkHttp 3.12.13` — это последняя версия OkHttp, совместимая с Android 4.4 KitKat. При отказе от KitKat в будущем библиотеку можно будет обновить до актуальной 4.x/5.x.
   - `minifyEnabled false` в релизной сборке: R8/ProGuard отключен, сборка не оптимизируется по размеру.

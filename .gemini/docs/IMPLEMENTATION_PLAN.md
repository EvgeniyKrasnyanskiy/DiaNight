# План реализации новых функций: Разделение кнопок, защита от выгорания, проверка обновлений, кнопка выхода и локальный обмен (Broadcast)

Этот документ описывает технические решения для добавления новой функциональности в приложение DiaNight на основе запроса пользователя.

---

## Вопросы для согласования с пользователем

> [!IMPORTANT]
> **1. Мигание разделителя часов (Двоеточия):**
> Сейчас двоеточие имеет эффект плавного затухания/нарастания ("дыхания") с периодом ~1.4 секунды.
> *   **Вариант А:** Замедлить текущее плавное дыхание (сделать период ~2-2.5 секунды).
> *   **Вариант Б:** Перейти на классическое дискретное мигание (включается раз в секунду: 0.5с горит, 0.5с скрыто).
> *Мы предлагаем оставить текущую анимацию, но замедлить шаг изменения прозрачности, чтобы сделать её плавнее и менее отвлекающей.*
>
> **2. Частота обновления IoB (Insulin on Board):**
> *   *Ответ на вопрос:* Да, IoB уже обновляется каждые 10 секунд совместно с основным запросом сахара (метод `fetchIoBData` вызывается сразу при успешном получении SGV). Если данных IoB нет (например, вернулось отрицательное значение или нет инсулина в xDrip+), компонент автоматически скрывается (`View.GONE`). В новом режиме локального обмена (Broadcast) IoB не транслируется стандартным пакетом, поэтому при переключении на локальный источник он будет скрываться.

## Предлагаемые изменения

### 1. Разделение кнопок в настройках
*   Внизу `activity_settings.xml` кнопка `btnSaveBottom` («Сохранить и выйти») будет заменена на горизонтальный `LinearLayout` с двумя кнопками:
    *   **«Отмена»** (`btnCancelBottom`) — цвет фона `@color/bg_input` (серый), закрывает экран настроек без сохранения (`finish()`).
    *   **«Сохранить»** (`btnSaveBottom`) — цвет фона `@color/colorPrimary` (фиолетовый акцент), сохраняет настройки и закрывает экран (`saveSettings()`).

### 2. Защита от выгорания для пиктограммы колокольчика
*   В `MainActivity.java` в задаче `pixelShiftRunnable` (которая выполняется каждые 2 минуты) мы добавим смещение не только для `centralClickArea` (часы/сахар), но и для всего `statusBarContainer` (верхней панели, содержащей шестеренку настроек, батарею, предупреждения, колокольчик оповещений и кнопку выхода).
*   Смещение всей верхней панели на случайную величину от -8 до +8 пикселей по осям X и Y защитит от выгорания дисплея **все статические значки статус-бара сразу**.

### 3. Проверка обновлений с GitHub
*   Добавим CardView «Обновление приложения» в `activity_settings.xml`.
*   Поля:
    *   Флажок `chkAutoCheckUpdates` — «Проверять обновления автоматически» (сохраняется в `SharedPreferences`, по умолчанию `true`).
    *   Кнопка `btnCheckUpdate` — «Проверить» (запускает ручную проверку).
    *   Кнопка `btnDownloadUpdate` — «Скачать APK» (изначально скрыта, появляется при обнаружении новой версии).
    *   Текстовое поле `tvUpdateStatus` — статус проверки (например, "Установлена актуальная версия" или "Доступна новая версия: 1.1.27").
*   В `SettingsActivity.java`:
    *   При запуске настроек (если включена автопроверка) или по нажатию на кнопку «Проверить» будет выполняться асинхронный HTTP-запрос к GitHub API: `https://api.github.com/repos/EvgeniyKrasnyanskiy/DiaNight/releases/latest`.
    *   Будет производиться парсинг тега версии (например, `v1.1.27`) и сравнение с локальной версией из `versionName`.
    *   Сравнение версий будет производиться покомпонентно (Major.Minor.Build) для корректности.
    *   При обнаружении новой версии показывается кнопка «Скачать APK», нажатие на которую открывает в браузере прямую ссылку на APK-файл (или страницу релиза).

### 4. Добавление кнопки «Выход» (крестик) на главный экран
*   Создадим векторное изображение крестика `ic_close.xml` в `res/drawable`.
*   Добавим `ImageView` с идентификатором `ivExit` в `activity_main.xml` в правый угол `statusBarContainer`.
*   Сместим `ivAlarmBell` левее от крестика с безопасным отступом в `16dp`, чтобы исключить случайные нажатия при попытке выключить будильник.
*   В `MainActivity.java`:
    *   Привяжем `ivExit` и установим обработчик клика на вызов `finish()` (выход из приложения).
    *   Добавим управление прозрачностью `ivExit` в методы `fadeControlsIn()` и `fadeAttributesOut()`, чтобы кнопка скрывалась по таймауту неактивности вместе с остальными элементами управления.

### 5. Локальный обмен данными без сети (Broadcast)
*   Добавим CardView «Источник данных» в начало настроек (`activity_settings.xml`).
*   Внутри будет `RadioGroup` с двумя опциями:
    1.  **«Сетевой (WiFi / xDrip+ Web Service)»** (по умолчанию) — текущая схема с запросом по IP.
    2.  **«Локальный (Broadcast от xDrip+ без сети)»** — получение данных напрямую через локальные интенты Android.
*   Если выбран локальный режим, поля ввода IP и ключа визуально отключаются (или показывается информационная подсказка).
*   В `MainActivity.java`:
    *   При запуске считывается сохраненный источник данных.
    *   Если выбран сетевой режим, запускается стандартный опрос по сети.
    *   Если выбран локальный режим, сетевой опрос отключается, и регистрируется динамический `BroadcastReceiver` для действия `com.eveningoutpost.dexdrip.BgEstimate`.
    *   При получении интента считываются экстра-данные:
        *   `com.eveningoutpost.dexdrip.Extras.BgEstimate` (double, значение сахара в mg/dL, конвертируется в mmol/L делением на 18.0).
        *   `com.eveningoutpost.dexdrip.Extras.BgSlopeName` (string, направление тренда, конвертируется в стрелочки).
    *   При локальном обмене IoB скрывается (`View.GONE`), так как не передается в широковещательном пакете.
    *   В `AndroidManifest.xml` добавляется секция `<queries>` для видимости пакета `com.eveningoutpost.dexdrip` на Android 11+.

## План верификации

### Ручное тестирование на эмуляторе/устройстве:
1.  **Проверка разделения кнопок:**
    *   Зайти в настройки.
    *   Нажать «Отмена» — настройки должны закрыться без сохранения.
    *   Изменить любой параметр, нажать «Сохранить» — настройки должны примениться, активироваться и закрыться.
2.  **Проверка выгорания (pixel shift):**
    *   Временное уменьшение интервала пиксель-шифта в коде до 5 секунд для быстрого тестирования.
    *   Визуальное подтверждение, что верхний статус-бар плавно смещается в случайном направлении вместе с центральным блоком.
3.  **Проверка кнопки выхода:**
    *   Тапнуть по экрану, чтобы отобразились элементы управления.
    *   Нажать крестик в правом верхнем углу — приложение должно корректно закрыться.
    *   Убедиться, что отступ между колокольчиком и крестиком достаточен и не мешает нажатию на колокольчик.
4.  **Проверка источника данных:**
    *   Переключить в "Локальный (Broadcast)". Проверить отключение/скрытие сетевых полей ввода.
    *   Проверить, что опрос сети прекратился.
    *   Сэмулировать отправку локального Broadcast (через adb или установив xDrip+ на устройство) и проверить появление сахара на экране.
5.  **Проверка обновления с GitHub:**
    *   Нажать кнопку «Проверить» в настройках.
    *   Убедиться, что запрос проходит успешно, корректно отображается статус.
    *   Для проверки отображения кнопки «Скачать» временно прописать в коде заниженную текущую версию (например, `1.1.0`), нажать «Проверить», убедиться в появлении кнопки «Скачать APK», нажать её и проверить переход в браузер.

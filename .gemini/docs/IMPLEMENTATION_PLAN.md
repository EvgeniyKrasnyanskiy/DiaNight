# Улучшение автопоиска мастера xDrip+ в локальной сети

Этот документ описывает планируемые изменения для повышения надежности, точности и скорости автоматического поиска мастер-устройства xDrip+ в приложении DiaNight.

---

## 1. Проблемы текущей реализации автопоиска

1. **Ненадежное получение IP-адреса устройства:**
   Используемый метод `wm.getConnectionInfo().getIpAddress()` в современных версиях Android (10+) часто возвращает `0.0.0.0` без разрешений `ACCESS_FINE_LOCATION` и `ACCESS_WIFI_STATE`. Это приводит к тому, что приложение сканирует неверную дефолтную подсеть `192.168.1.X`.
2. **Игнорирование хостов с включенным API Secret:**
   Если в xDrip+ на мастере включен API Secret, то при запросе `/sgv.json?brief_mode=Y` без заголовка авторизации он возвращает код `401 Unauthorized`. Метод `response.isSuccessful()` расценивает это как неудачу, и хост игнорируется.
3. **Очереди запросов в OkHttp:**
   По умолчанию `OkHttpClient` имеет ограничение `maxRequests = 64`. 254 запроса делятся на очереди, что замедляет сканирование.
4. **Маленький таймаут (600 мс):**
   При плохом Wi-Fi соединении или когда мастер-телефон находится в режиме энергосбережения, он может не успеть ответить за 600 мс.

---

## 2. Предлагаемые изменения

### Настройка параллелизации, таймаутов и обнаружения 401
Мы заменим `startNetworkAutoDiscovery()` и вспомогательные методы в [SettingsActivity.java](file:///h:/DiaNight/app/src/main/java/com/diaclock/nightstand/SettingsActivity.java):

*   **Определение локального IP-адреса:**
    Будем использовать обход сетевых интерфейсов через `NetworkInterface.getNetworkInterfaces()`. Это позволяет получить реальный IP в локальной сети без каких-либо опасных разрешений.
*   **Обработка кода 401:**
    Если устройство ответило кодом `200` ИЛИ `401`, мы считаем, что xDrip+ успешно найден. Если это `401`, мы дополнительно выводим предупреждение о необходимости проверить API Secret.
*   **Параллелизация через Dispatcher:**
    Настроим собственный `Dispatcher` в `OkHttpClient` с лимитом `maxRequests = 254` и `maxRequestsPerHost = 254`. Это позволит выполнить все 254 запроса одновременно.
*   **Увеличение таймаута:**
    Увеличим таймауты до `1500 мс`. С учетом полной параллелизации сканирование по-прежнему займет не более 1.5 секунд, но станет намного надежнее.

*   Добавить метод `getLocalIpAddress()` взамен устаревшего `getWifiIpAddress()`.

*   Обновить обработку `response` в `scanClient`: проверять `response.isSuccessful() || response.code() == 401`.

## 4. План проверки и верификации

### Ручное тестирование
1. Запустить приложение на устройстве, подключенном к локальной сети.
2. Нажать на иконку поиска (лупу) в настройках.
3. Убедиться, что сканирование проходит быстро (в пределах 1.5–2 секунд).
4. Проверить сценарии:
   - xDrip+ активен в той же сети без API Secret -> Успешное обнаружение и заполнение IP.
   - xDrip+ активен с установленным API Secret -> Успешное обнаружение (вывод сообщения о необходимости ввода API Secret).
   - xDrip+ выключен или устройство в другой сети -> Показ сообщения о том, что мастер не найден.
